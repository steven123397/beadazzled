# ADR-0010: 设置页采用左侧栏目导航与分栏目路由

状态：已接受（2026-11-03）
影响模块：`settings`、`shell`

## 背景

设置页最初是一篇单页文档，六个区块依次向下排列。功能面稳定后暴露出两个问题：

1. 区块之间的高度互相挤占。工作区列表随注册项目数线性增长，十几个项目就能把「同步 / 诊断 / 关于」推到很远；
2. 所有区块共用一次渲染。用户只改语言时，工作区列表和诊断说明也一起参与布局。

对比 Linear、VS Code 等桌面工具的设置界面，它们都把设置拆成左侧栏目、每栏一页。

## 决策

- 设置页内部增加一条固定宽度的左侧栏目导航：General / bd / Workspaces / Sync / Diagnostics / About。
- 每个栏目一条路由：`#/settings/general`、`#/settings/bd`、`#/settings/workspaces`、`#/settings/sync`、`#/settings/diagnostics`、`#/settings/about`。
- `#/settings` 重定向到 `#/settings/general`；未知栏目同样回到 `general`。
- 栏目切换走前端路由，不触发数据加载；栏目组件仍按需渲染，只有当前栏目进入 DOM。
- 工作区列表不再使用内嵌滚动，由页面自身滚动承载。

## 后果

- 工作区列表可以随项目数增长，不再挤占其他设置；长列表回到浏览器/WebView 的单一滚动上下文。
- 每个栏目可深链（`#/settings/diagnostics` 可直接发给协作者），浏览器前进/后退可用。
- 窄窗下设置页变成三栏（应用侧栏 + 设置栏目 + 内容）；1000px 时内容列约 550px，表单改为单列可用，但观感需要后续回归检查。
- E2E 需要按栏目访问，测试里不再假设所有区块同时存在。
- 设置 chunk 仍然只在进入设置路由时加载，首屏体积不变。

## 被拒绝的备选

- **单页锚点导航**：视觉上有左栏，但工作区仍必须限高滚动，没有解决列表增长问题。
- **顶部标签栏**：不占第三栏，但栏目增至 6 个后标签拥挤，且与左栏导航的信息架构不同。
- **折叠面板**：解决高度但不解决「一次渲染全部区块」，且默认折叠会藏住状态信息。
