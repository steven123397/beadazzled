# Board 滚动帧率（2026-11-02）

状态：验收记录，回答 `bza-m4s` 的「1000 卡片滚动 60fps」。不改预算阈值。

关联：`bza-m4s`（Board 派生列与卡片）、[SPEC-board](../spec/SPEC-board.md)
「性能」与验收标准 13、`bza-z2l`（Board 测试与 E2E）、`bza-bee`（测量脚本与
CI 接线）、`CONSTRAINTS.md` 的「列表滚动」。

## 问题

看板要求 1000 张卡片整体滚动保持 60fps，且拖动 overlay 不引起整列重排。看板
每列独立虚拟化，性能取决于单列虚拟窗口、卡片是否定高，以及滚动一列时其它列
是否跟着 Reconciliation。

## 方法

1. 沿用列表滚动测量的同一脚本：`VITE_E2E=1` 生产构建 + `vite preview` +
   Chromium，注入 1000 条固定票据。
2. 新增 `--view=board`：打开 `#/w/p1/board`，滚动 Ready 列
   （`[data-column-id="ready"] [role="list"]`）。该列容纳全部约 570 条 open 票据，
   是看板中最长的一列。
3. 两个场景，各跑 5 轮：
   - `board-steady`：每帧 48px，120 帧；
   - `board-fling`：每帧 240px，150 帧。
4. 采样与门槛同列表：p50/p95 取 5 轮中位数，`max` 取所有轮次实际出现的最长帧；
   p50 < 20ms、p95 < 24ms、max < 50ms，移动距离低于场景下限判失败。

命令：`npm run measure:scroll -- --view=board`。

环境：Windows 11、i5-13500H、平衡电源计划；测量时浏览器与其他应用同时运行。

## 结果

生产构建，两个场景各 5 轮：

| 场景 | p50（中位） | p95（中位） | 最坏帧 | 移动距离 |
|---|---:|---:|---:|---:|
| board-steady 48px/frame，从 0 | 16.7ms | 19.0ms | 22.5ms | 5,760px |
| board-fling 240px/frame，从 0 | 16.6ms | 18.2ms | 20.3ms | 36,000px |

单轮明细：

| run | steady p50/p95/max | fling p50/p95/max |
|---:|---|---|
| 1 | 16.7 / 19.0 / 21.8 | 16.8 / 18.2 / 20.3 |
| 2 | 16.8 / 19.3 / 20.2 | 16.7 / 18.0 / 19.3 |
| 3 | 16.7 / 19.0 / 20.6 | 16.6 / 18.2 / 20.3 |
| 4 | 16.7 / 19.2 / 22.5 | 16.6 / 18.5 / 19.7 |
| 5 | 16.5 / 18.9 / 20.3 | 16.6 / 18.6 / 19.8 |

## 结论

1. **达标**：中位帧 16.6–16.7ms（满帧 60Hz），p95 18.2–19.0ms，最坏帧
   20.3–22.5ms；快速 fling 移动 36,000px，没有持续掉帧。
2. **定高卡片是前提**：卡片高度固定为 `--card-height: 120px`，列虚拟化不需要
   逐项测量；标题限制 3 行。若后续允许卡片自适应高度，必须改用动态测量并重新
   跑本测量。
3. **只验证了滚动**：拖动 overlay、pending 状态与键盘移动属于 `bza-ni9`；
   零 bd 调用与拖动静止重排属于 `bza-z2l`。
4. **CI 接线仍归 `bza-bee`**：脚本目前只本地运行，`CONSTRAINTS.md` 中该项目的
   接线状态不变。
