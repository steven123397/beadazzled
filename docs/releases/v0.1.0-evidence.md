## 发布步骤（人工，按顺序）

以下步骤尚未执行；每完成一步就把结果补进上面的证据表。

```bash
# 1. 代码进入 main，并打 tag（tag 必须与三处版本一致）
git checkout main && git merge --ff-only feat/phase8-release
git tag -a v0.1.0 -m "beadazzled v0.1.0" && git push origin main --tags

# 2. 先建 draft release，避免 latest 端点指向半成品
gh release create v0.1.0 --draft --title "beadazzled v0.1.0" \
  --notes-file docs/releases/v0.1.0.md

# 3. 上传资产：exe 与 .sig 先上传，latest.json 最后上传
gh release upload v0.1.0 src-tauri/target/release/bundle/nsis/beadazzled_0.1.0_x64-setup.exe
gh release upload v0.1.0 src-tauri/target/release/bundle/nsis/beadazzled_0.1.0_x64-setup.exe.sig
gh release upload v0.1.0 src-tauri/target/release/bundle/nsis/latest.json

# 4. 发布（此时 releases/latest 才指向 v0.1.0）
gh release edit v0.1.0 --draft=false --latest

# 5. 第三层证据：下载回来重新验签
mkdir -p /tmp/v010 && cd /tmp/v010
curl -LO https://github.com/steven123397/beadazzled/releases/latest/download/latest.json
curl -LO https://github.com/steven123397/beadazzled/releases/latest/download/beadazzled_0.1.0_x64-setup.exe
curl -LO https://github.com/steven123397/beadazzled/releases/latest/download/beadazzled_0.1.0_x64-setup.exe.sig
npm --prefix <repo> run verify:release -- --installer ./beadazzled_0.1.0_x64-setup.exe
```

回滚：更新器拒绝降级，所以把 `latest` 指回旧版本对已安装用户**无效**。
发现坏版本时的唯一回滚路径是发布一个更高的补丁版本（如 v0.1.2）；在
`gh release edit --draft=false` 之前发现问题，直接改成 draft 或删除即可，
此时还没有任何用户拿到它。

## 自动更新

- 端点：`https://github.com/steven123397/beadazzled/releases/latest/download/latest.json`。
- 启动后 10s 检查一次；About 提供手动检查；失败在 About 显示原因，不打扰启动。
- 更新包必须通过内置公钥验签；版本不更高或签名不匹配时拒绝。
- `requireSignedVersion: true`：清单本身未签名，启用它之后，安装包签名里记录的
  版本必须与清单声明的版本一致，避免有人只拿到 GitHub 写权限就用旧版本的有效签名
  配合虚高的版本号强制降级。用当前 Tauri CLI 签出的包（签名注释含 `version:`）
  才能通过，v0.1.0 已满足。
- 签名私钥不在仓库内；口令用 DPAPI 保护。首次发布前必须离线备份，
  丢失会导致已安装用户无法自动更新。
- **更新闭环未完整演示**：需要先发布 v0.1.0，再发布 v0.1.1 才能走
  「确认 → 下载 → 验签 → passive 安装 → 自动重启」；本地已验证 `.sig` / `latest.json`
  一致性及篡改拒绝（`verify:release`）。
